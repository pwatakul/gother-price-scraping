# REQ-002: Price History & Automated Scraping
_Version: 1.1 | Supersedes [[REQ-002-v1.0]]_

## What changed from v1.0
| Change | Reason |
|--------|--------|
| F-001–F-009 implemented | Full implementation pass — dual-write, scheduled configs CRUD, cron scheduler, price-history query/trend API |
| Migration numbering renumbered 012–015 (not 007–013 as originally planned) | Part A's REQ-001 work used migration numbers 007–011 for hotel-master-import/scrape-method/dimension columns, which the original REQ-002 plan hadn't anticipated. `product_type` enum dropped entirely — not needed since REQ-004 (multi-product) is descoped and ADR-002 already gives `hotel_price_history` a direct FK to `hotels` |
| `scheduled_scrape_configs` gained a `method` column (not in original schema) | Scheduled runs needed an explicit scraper-method choice (serpapi/chatgpt/gemini/both) rather than an implicit hardcode, decided during implementation |
| Currency rates sourced from the existing static table (`normalizer::currency::get_exchange_rate`), not a live BOT/exchangerate-api integration | Live rate-provider integration was never actually in scope for v1.0 either — this makes explicit what "auditable currency conversion" means in practice for this system |
| F-010/F-011 (retention cleanup, admin trigger) explicitly deferred, not built | Retention already resolved to "keep forever" (RETENTION_DAYS=0, disabled) in v1.0's own open questions — building unused cleanup code was skipped |
