# REQ-001: Hotel Price Scraping — Core Module
_Version: 1.4 | Supersedes [[REQ-001-v1.3]]_

## What changed from v1.3
| Change | Reason |
|--------|--------|
| **F-022 widened** — recognized providers are now Gother, Agoda, Trip, Wink **plus Booking.com, Expedia, Priceline, Traveloka, Klook and the hotel's own rate (`direct`)** | SerpAPI returns 11–26 real, date-specific prices per hotel and the four-provider filter discarded nearly all of them: 7 of 20 hotels reported "no rates" while Booking/Expedia/Priceline prices sat unused in the same response. See [[ADR-009-widen-provider-allowlist]] |
| **F-020 removed** — the ChatGPT scraper no longer exists | LLM scrapers structurally cannot return live per-date rates; ChatGPT was never configured and produced 0 rows. See [[ADR-007-remove-chatgpt-scraper]] |
| **F-023/F-024 resolved** — device and login state are *recorded, never varied* | v1.3 flagged these as unverified. Now tested: SerpAPI documents no `device` parameter and ignores one supplied, and desktop vs mobile showed **zero price differences across 69 sources**. Login/member rates have no API parameter and no credentials exist. See [[ADR-010-drop-device-and-member-dimensions]] |
| Source normalization moved into `scraper/providers.rs` and shared by all scrapers | Each scraper previously had its own matching logic — two places to drift. A substring match was also filing **EaseMyTrip.com** and **Clicktrip.com** as Trip.com |
| `method=both` duplication risk narrowed | Only SerpAPI and Gemini remain, and Gemini returns no rows in practice |

## Scope note
This version documents the **core scraping/API/Excel/evidence** functionality. Price history storage, scheduled scraping and analytics remain [[REQ-002-v1.1]], [[REQ-008-v1.1]] and [[REQ-003-v1.0]] scope.

## Open Risks
- [ ] **Gother has no data source.** Not reachable via SerpAPI either — a 5-hotel probe returned 36 distinct sources and Gother appeared in none. Requires Gother's own API (`GotherScraper` is written and waiting on `GOTHER_API_URL`/`GOTHER_API_KEY`). Until then the win-rate and parity analytics have no reference price. See [[ADR-009-widen-provider-allowlist]].
- [ ] **Hotel-direct detection is heuristic.** SerpAPI exposes no "official rate" flag, so `direct` is inferred from the source name resembling the hotel's. It is conservative and unit-tested, but it is the one classification that can fail silently and plausibly — spot-check it when the hotel list changes materially.
- [ ] **Gother WHO ID**: still unconfirmed; `who_id` deserializes as optional and is never fabricated.
- [ ] **Wink**: no data source. Column permanently blank until Wink/HyperGuest access is investigated.
- [ ] **Device conclusion is source-specific.** It says SerpAPI's Google Hotels aggregation does not vary by device — not that OTAs never do. A direct per-OTA scraper could see mobile-only rates.
