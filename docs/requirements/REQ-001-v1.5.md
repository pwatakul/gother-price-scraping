# REQ-001: Hotel Price Scraping — Core Module
_Version: 1.5 | Supersedes [[REQ-001-v1.4]]_

## What changed from v1.4
| Change | Reason |
|--------|--------|
| **`method=both` is now precedence-ordered, not concatenated** — SerpAPI is authoritative, Gemini runs only when the primary tier returned nothing | Closes the "`method=both` duplication" open risk carried since v1.3. The two sources are not interchangeable: SerpAPI reads live rates, Gemini answers from training knowledge and was measured quoting Agoda, Trip.com and Booking.com all at ฿6,551 when the real Trip.com rate was ฿6,773. See [[ADR-011-serpapi-primary-gemini-fallback]] |
| **New F-029** — every price row records which scraper produced it (`via_method`) | Without provenance an AI estimate is indistinguishable from a scrape in every analytics view — the situation that forced deleting the mock rows wholesale rather than filtering them |
| Explicitly choosing a fallback method still runs it as primary | `method=gemini` means the user asked for Gemini; only `both` defers it |

## Scope note
This version documents the **core scraping/API/Excel/evidence** functionality. Price history storage, scheduled scraping and analytics remain [[REQ-002-v1.1]], [[REQ-008-v1.1]] and [[REQ-003-v1.0]] scope.

## Verification
Live `method=both` run over the 20 seeded hotels:
- **Primary-wins path:** 91 rows written, **all `via_method='serpapi'`**, zero Gemini rows across 16 hotels.
- **Fallback path:** for the 4 hotels SerpAPI could not resolve (Amanpuri, Rayavadee Krabi, Shangri-La Bangkok, The Sukhothai Bangkok) Gemini *was* attempted — confirmed by log — and returned no rates, so those hotels failed honestly with `serpapi: failed (…); gemini: returned no rates`.
- 50/50 backend tests pass, including the precedence rule; `tsc --noEmit` clean.

## Open Risks
- [ ] **Gother has no data source.** Not reachable via SerpAPI either (36 distinct sources across 5 Thai hotels, none of them Gother). Requires Gother's own API. Until then the win-rate and parity analytics have no reference price.
- [ ] **Fallback trigger semantics will need revisiting when Gother connects.** The rule is "primary tier produced zero rows". Once Gother supplies its own rate, a Gother-only result with no OTA prices would no longer trigger the fallback, even though that is still a gap in the comparison. See [[ADR-011-serpapi-primary-gemini-fallback]].
- [ ] **A labelled fabricated price can still be stored.** Gemini rows are tagged and badged, not prevented. Spot-check any `via_method='gemini'` row before trusting it.
- [ ] **Hotel-direct detection is heuristic** — SerpAPI exposes no "official rate" flag. Conservative and unit-tested, but the one classification that can fail silently and plausibly.
- [ ] **Gother WHO ID**: unconfirmed; never fabricated.
- [ ] **Wink**: no data source; column permanently blank.
