# REQ-001: Hotel Price Comparison System
_Version: 1.0 | Superseded by [[REQ-001-v1.1]]_

## Raw Requirement (plain language)
Build a tool that lets users upload a list of hotels, specify check-in/check-out dates and guest counts, then automatically scrape prices from multiple online travel agencies (OTAs) and compare them against Gother's own prices. The output should show side-by-side prices per hotel per source and be exportable as an Excel report. Built as a competition entry for Gother Challenge 2026.

## Goal
Enable Gother's team (and competition judges) to quickly see how Gother's hotel prices compare to competing OTAs (Agoda, Booking.com, Trip.com, etc.) for a given set of hotels, dates, and occupancy. Highlights cases where Gother is cheaper or more expensive than the market.

## Acceptance Criteria
- [x] User can create a hotel group and upload hotels via Excel (.xlsx)
- [x] User can add/remove individual hotels from a group
- [x] User can create a scrape job by selecting a hotel group, dates, rooms, and adults
- [x] Scrape job fetches prices from SerpAPI (Google Hotels) and Gother API
- [x] All prices are normalized to THB
- [x] Room types and meal plans are normalized to standard labels
- [x] User can see real-time progress (total / completed / failed per hotel)
- [x] Completed job shows a price comparison table per hotel with all OTA sources
- [x] User can export results as an Excel report
- [x] Previously scraped prices are cached in Redis to avoid redundant API calls
- [x] User can download an Excel import template for hotel lists

## Non-Functional Requirements
| ID | Description |
|----|-------------|
| NF-001 | Performance: scrape jobs process hotels in parallel batches (default concurrency = 3) |
| NF-002 | Caching: scraped prices cached in Redis for PRICE_CACHE_TTL_SECONDS (default 1 hour) |
| NF-003 | Reliability: failed hotel scrapes are retried up to WORKER_RETRY_COUNT times |
| NF-004 | Portability: full stack runs via Docker Compose (postgres + redis + rabbitmq + backend + frontend) |
| NF-005 | Observability: structured tracing via `tracing` crate; all scrape errors are logged |

## Out of Scope
- User authentication / multi-user support (no auth in v1.0)
- Direct browser-based scraping of OTA websites (uses APIs only)
- Historical price tracking / trend charts
- Email or webhook notifications when a job completes
- WebSocket push for real-time progress (frontend polls instead)

## Dependencies
- SerpAPI account with Google Hotels engine access (`SERPAPI_KEY`) — see [[ADR-001-scraper-choice]]
- Gother internal API credentials (`GOTHER_API_URL`, `GOTHER_API_KEY`)
- PostgreSQL, Redis, RabbitMQ (provided via Docker Compose)
- Optional: Google Gemini API key for AI normalization (`GEMINI_API_KEY`)
