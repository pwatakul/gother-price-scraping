# REQ-009: Login Authentication with Role Field
_Version: 1.0_

## Raw Requirement (plain language)
> I need a simple authentication. I need user to login to website and future I expect user to have roles. So difference user will can do differenry. Now need to login only and default user is admin and password admin1234!.

## Goal
Nobody reaches the platform without signing in, and every account carries a role
so that restricting what different users can do later is a small change rather
than a schema migration and a backfill.

Two things are explicitly in scope now, and one explicitly is not:

| | In scope for v1.0 |
|---|---|
| ✅ | Login, logout, session persistence across reloads |
| ✅ | A `role` column, carried through the session token and shown in the UI |
| ❌ | **Enforcing** roles — a `viewer` can currently do everything an `admin` can |

## Functional Requirements

### F-001 — Every API endpoint requires a session
All routes under `/api` reject requests without a valid session cookie with
**401**, except:

| Route | Why it is public |
|---|---|
| `GET /api/health` | A container health probe carries no cookie |
| `POST /api/auth/login` | You cannot authenticate to authenticate |
| `POST /api/auth/logout` | Clearing a cookie must work even when the session has already expired |

The gate is applied to the **whole authenticated router at once**, not route by
route, so a route added in future is protected by default.

### F-002 — Seeded admin account
On first startup, when the `users` table is empty, the system creates:

- username `admin`
- role `admin`
- password from `ADMIN_PASSWORD`, or **`admin1234!`** when that variable is unset

Seeding is **idempotent**: it never runs again once any user exists, so a
password changed through the UI survives every restart and redeploy.

### F-003 — Login
`POST /api/auth/login` with `{username, password}`. Username matching is
case-insensitive. On success the response sets an httpOnly session cookie and
returns `{id, username, role, using_default_password}`.

**A wrong password and an unknown username return the identical message and
status** (`401`, "Invalid username or password"), so the API cannot be used to
discover which accounts exist.

### F-004 — Session restore
`GET /api/auth/me` returns the signed-in user. The frontend calls it once on
mount; because the cookie is httpOnly there is no other way for the SPA to know
whether it is signed in.

While that call is in flight the app shows a spinner, **not** the login screen —
otherwise every page reload flashes a login form before landing back where the
user was.

### F-005 — Change password
`POST /api/auth/change-password` with `{current_password, new_password}`. The
current password is required even though the caller is already authenticated,
so an unattended session cannot be used to lock the owner out. New passwords
must be at least 8 characters and different from the current one.

### F-006 — The default password must not become permanent
`using_default_password` is returned by `/auth/me` and `/auth/login`, computed
by checking the stored hash against the known default. While it is true the UI
shows a dismissible banner offering to change it. It clears itself once the
password is changed — no flag to reset, nothing to remember.

### F-007 — Roles are carried, not enforced
`role` is one of `admin` or `viewer` (a DB CHECK constraint), travels inside the
session token, and is displayed as a badge in the top bar. **No endpoint or
route checks it in v1.0.** This is stated here so nobody reads the badge as
evidence that a `viewer` is restricted.

### F-008 — Startup refuses to run without a signing secret
`JWT_SECRET` is required and must be at least 32 characters; the backend exits
with a clear message otherwise. A default or fallback key would let anyone who
has read the source mint a valid session cookie, which would make every
requirement above decorative.

## Non-Functional

| | Requirement |
|---|---|
| Password storage | Argon2id, per-user random salt, PHC string. Plaintext never leaves the request handler |
| Session lifetime | 12 hours |
| Cookie flags | `HttpOnly`, `SameSite=Strict`, `Path=/`. `Secure` is **off** while the app is served over plain HTTP — see Open Risks |
| Failed logins | Logged at WARN with the attempted username |

## Out of Scope (v1.0)
- Self-service signup, user management UI, password reset by email
- Session revocation — see Open Risks
- Multiple accounts (the seeded `admin` is the only user until one is added directly)
- Per-role route restrictions (F-007)

## Open Risks
| Risk | Note |
|---|---|
| **No revocation** | A stolen cookie stays valid for up to 12 hours. Changing the password does **not** invalidate sessions already issued. Acceptable for an internal tool; a `token_version` column on `users` is the small fix when it isn't |
| **`Secure` cookie flag off** | Required today because the app is served over HTTP on localhost — a `Secure` cookie would simply never be sent and login would silently fail. **Must be turned on when this is served over HTTPS** |
| **CORS is still `allow_origin(Any)`** | Harmless with same-origin cookies (browsers refuse credentialed requests against a wildcard), but it should be narrowed before the app is exposed beyond localhost |
| **Roles do nothing yet** | F-007. The next requirement that adds a `viewer` user must also add enforcement, or the role will be misleading |

## Acceptance Criteria
- [x] `GET /api/hotels` without a cookie returns 401; `GET /api/health` returns 200
- [x] An unknown path returns 404, not 401
- [x] Login with `admin` / `admin1234!` returns 200 and sets `HttpOnly; SameSite=Strict`
- [x] A wrong password and an unknown username return byte-identical error bodies
- [x] The cookie authorises subsequent requests; after logout the same request returns 401
- [x] A token signed with a different secret is rejected (unit test)
- [x] The backend refuses to boot with `JWT_SECRET` missing or shorter than 32 chars
- [x] Restarting the backend does not re-seed or reset the admin password
- [x] Changing the password invalidates the old one and clears `using_default_password`
