## New Open Risks (implementation-time findings)
- [ ] **Gother WHO ID**: not confirmed whether Gother's internal API returns a WHO ID field today. `who_id` deserializes as optional and is never fabricated — needs verification against the real API before F-025's acceptance criterion can be called fully met.
- [ ] **Device/login-state fidelity**: SerpAPI and the Gother API have no documented parameters for varying results by device or login state. The dimensions are recorded on every job/result as configuration metadata, but nothing today proves the underlying scrape was actually performed differently per axis.
- [ ] **`method=both` duplication**: SerpAPI and ChatGPT can both return an `agoda`/`trip` row for the same hotel when `method=both`, with no reconciliation/dedup — the report will show multiple rows per source in that case. Not addressed in this pass.
- [ ] **Wink**: no real data source integrated. Column is permanently blank until a follow-up investigates Wink/HyperGuest access.
