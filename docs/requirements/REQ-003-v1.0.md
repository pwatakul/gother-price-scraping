# REQ-003: Market Analytics Dashboard
_Version: 1.0_

## Raw Requirement (plain language)
Product Owner and Business Development need to open the system and immediately see the world market — without having to manually trigger a scrape job. They want to see price trends over time, know where Gother stands versus competitors, identify which hotels Gother is losing on price, and export the intelligence as reports. The dashboard should be a business tool, not a technical one.

## Goal
Transform the raw price history data into actionable market intelligence. Enable PO and BD to make pricing decisions backed by real OTA market data — not guesses. Answer three core questions at a glance:
1. **Where is Gother winning?** (hotels where Gother is cheapest)
2. **Where is Gother losing?** (hotels where Gother is more expensive than competitors)
3. **Is the gap getting better or worse over time?** (trend direction)

## Target Users
| User | Need |
|------|------|
| Product Owner | Market overview, competitive positioning, identify pricing action items |
| Business Development | Export reports for partner meetings, spot market opportunities |
| Data Analyst (future) | Raw data export, custom queries |

## Acceptance Criteria
- [ ] Dashboard home shows market overview: total hotels tracked, % Gother is cheapest, avg price gap vs market
- [ ] Price trend graph: select a hotel → see price over time per OTA source (line chart)
- [ ] Market position table: hotel list sorted by price gap (Gother vs cheapest competitor)
- [ ] Competitor price heatmap: rows = hotels, columns = OTA sources, cells = price or color-coded gap
- [ ] Date range filter applies across all views (last 7d / 30d / 90d / custom)
- [ ] "Win rate" metric: % of days/checks where Gother had the best price per hotel
- [ ] Export: download current view as Excel report
- [ ] All data comes from `hotel_price_history` (no scrape triggered by viewing dashboard)
- [ ] Rate parity violations automatically flagged when Gother exceeds best OTA by > threshold % (configurable, default 5%)
- [ ] Booking window chart shows how prices evolve as check-in date approaches (days_in_advance axis)

## Functional Requirements
| ID | Description | Priority |
|----|-------------|----------|
| F-001 | **Market Overview Card** — total hotels tracked, % where Gother is cheapest today, avg THB difference vs best OTA | High |
| F-002 | **Price Trend Chart** — line graph: hotel × source × time; x-axis = scraped_at date, y-axis = price_thb; filterable by source | High |
| F-003 | **Market Position Table** — one row per hotel; columns: hotel name, Gother price, best OTA price, difference (THB + %), winning/losing badge | High |
| F-004 | **Competitor Heatmap** — hotel vs OTA source grid; color-coded: green = Gother cheaper, red = Gother more expensive, grey = no data | High |
| F-005 | **Win Rate Metric** — per hotel: % of historical data points where Gother was the cheapest source | Medium |
| F-006 | **Date Range Filter** — global filter: last 7d, 30d, 90d, custom range; applies to all analytics | High |
| F-007 | **Lookahead Filter** — filter by check-in lead time (e.g., show only prices for stays 30 days out) | Medium |
| F-008 | **Hotel Group Filter** — filter all views by hotel group | High |
| F-009 | **Export Report** — download current dashboard view as Excel (market position table + trend data) | High |
| F-010 | **Price Alert Threshold** (optional) — flag hotels where Gother is more expensive than market by > X% | Low |
| F-011 | **Summary Stats API** — backend endpoints returning aggregated analytics from `hotel_price_history` via materialized views | High |
| F-012 | **URL param filter persistence** — all filters encoded as URL params (`?group=uuid&period=30d`) so views are bookmarkable and shareable | Medium |
| F-013 | **Rate Parity Alert** — automatically flag when Gother's price exceeds any OTA by more than a configurable threshold (default 5%); surface as badge on dashboard and optionally send email/webhook notification | High |
| F-014 | **Booking Window Analytics** — view how competitor prices change as arrival date approaches; x-axis = days_in_advance (derived: `checkin_date - DATE(scraped_at)`), y-axis = price_thb, lines per OTA source; reveals early-bird vs. last-minute pricing patterns | High |

## Non-Functional Requirements
| ID | Description |
|----|-------------|
| NF-001 | Dashboard must load in < 3 seconds for up to 200 hotels with 90 days of history |
| NF-002 | Analytics queries must use materialized views or pre-aggregated tables — no full `hotel_price_history` scan on page load |
| NF-003 | Charts must be readable on 1080p and above; mobile not required for v1 |
| NF-004 | No real-time refresh required; data is as of last scheduled scrape run |

## UI Components Needed
| Component | Description |
|-----------|-------------|
| `MarketOverviewCard` | KPI cards: total hotels, win rate %, avg price gap |
| `PriceTrendChart` | Line chart (recharts or similar) with source legend and date range slider |
| `MarketPositionTable` | Sortable table with winning/losing badge, price diff column |
| `CompetitorHeatmap` | Grid component with color-coded cells |
| `DateRangeFilter` | Shared filter component used across all views |
| `AnalyticsExportButton` | Triggers Excel download from API |
| `RateParityAlert` | Badge/banner on dashboard showing hotels with active parity violations |
| `BookingWindowChart` | Line chart: x = days_in_advance, y = price_thb, lines per OTA source |

## API Endpoints Needed (new)
| Method | Path | Description |
|--------|------|-------------|
| GET | `/analytics/overview` | Market overview KPIs |
| GET | `/analytics/market-position` | Hotel × source position table |
| GET | `/analytics/trend/:hotel_id` | Price trend time-series for one hotel |
| GET | `/analytics/heatmap` | Grid data for competitor heatmap |
| GET | `/analytics/export` | Download Excel analytics report |
| GET | `/analytics/parity-violations` | Hotels with active rate parity violations above threshold |
| GET | `/analytics/booking-window/:hotel_id` | Price-by-days-in-advance data for one hotel |

## Out of Scope (v1.0)
- Real-time price alerts / push notifications
- Predictive pricing / ML forecasting
- Per-user saved views / dashboards
- Mobile-responsive layout
- Flight or experience analytics (those follow hotel pattern once hotel is done)

## Dependencies
- [[REQ-002-v1.0]] — `hotel_price_history` must be populated before any analytics are meaningful
- [[REQ-005-v1.0]] — materialized views and query optimization strategy

## Open Questions
- [x] Which charting library? → Resolved: Recharts (React-compatible, lightweight, no extra dependencies)
- [x] Should "today's price" come from latest `hotel_price_history` entry, or trigger a live scrape? → Resolved: latest from `hotel_price_history` — dashboard never triggers a scrape (see acceptance criteria)
- [x] What is the primary sort order for the Market Position Table? → Resolved: sorted by price gap descending (biggest losers first — most actionable for PO/BD)
- [x] Do we need user-level saved filters / bookmarks in v1? → Resolved: No per-user saved views — filters persist via URL params only (bookmarkable, shareable) — see F-012
