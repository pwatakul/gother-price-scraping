# REQ-002: Price History & Automated Scraping
_Version: 1.2 | Supersedes [[REQ-002-v1.1]]_

## What changed from v1.1
| Change | Reason |
|--------|--------|
| **New F-012–F-014** — a hotel group carries saved price-search settings that can be edited, run in one click, and are shared with the scheduler | A search was reconfigured from scratch every run; nothing was remembered, so repeating last week's search meant re-entering it from memory |
| Dates stored as a **days-ahead offset**, not calendar dates | A saved config holding literal dates goes stale silently — it keeps querying a past date and just stops producing data. See [[ADR-012-group-search-config]] |
| **`scheduled_scrape_configs.method` dropped** (migration `022`); the scheduler reads `hotel_groups.search_method` | With the group as the source of truth, a per-schedule method is a second place to set the same thing, free to diverge silently — the dead-config problem migration `019` already corrected once |
| Scheduled runs still use the **fixed standard grid** for windows and stay params | The group config supplies the method only. [[ADR-006-booking-window-device-standard]] keeps every hotel's series on one x-axis, which per-group stay params would break |

## Scope notes
- A schedule now configures only *when* (`cron_expression`) and *whether* (`is_active`) to run. Method comes from the group; windows and stay params are system constants.
- Manual runs set `force_refresh: true` — an explicit press means "get current prices". Scheduled runs leave it false and accept cached rows.
- On-demand jobs via `POST /scrape-jobs` still accept free-form parameters; the saved config does not restrict the API, only the UI's one-click path.

## Open Risks
| Risk | Detail |
|------|--------|
| **Editing the config shifts the manual-search series** | Rooms/adults/LOS are recorded per row so history stays interpretable, but a mid-series config change shows as a step change in the manual-search trend. The scheduled series is unaffected. |
| **One-click runs are easy to repeat** | 20 hotels = 20 SerpAPI searches per press, against a ~250/month free tier. |
| **Two notions of "days ahead"** | `search_days_ahead` (configurable, manual runs) and the booking-window constants (fixed, scheduled runs) are independent by design but easy to conflate when reading the code. |
